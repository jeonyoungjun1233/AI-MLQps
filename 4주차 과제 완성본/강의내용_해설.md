# 4주차 강의 내용과 과제 연결

검토 자료: `02_강의PDF/04주차_강의자료.pdf`, 전체 5쪽. 아래는 강의 설명이며 실제 제출 수치는 두 JSON과 서술형 답안에서 확인합니다.

## 1. 파티션과 순서 (1~2쪽)

Kafka 토픽은 여러 파티션으로 나뉩니다. 오프셋은 파티션 안에서 증가하므로 토픽 전체의 하나의 순번이 아닙니다. 서로 다른 파티션에서 오프셋 0이 동시에 존재할 수 있습니다. 파티션 수가 고정된 실습에서 같은 지역구 키는 같은 파티션으로 가고, 그 범위에서 순서를 보존합니다. 민원 ID를 키로 삼으면 개별 민원의 상태 변화 순서를 지키는 데 적합합니다.

키는 순서 보장 범위와 부하 분산에 모두 영향을 줍니다. 파티션을 증설하면 같은 키의 배치 위치가 바뀔 수 있으므로 증설 전후의 순서까지 자동으로 보장되는 것으로 해석하면 안 됩니다. 강의의 200건 분포 61·76·63은 균등하게 나뉘지 않는 실제 사례이며, `key_to_single_partition`과 지역구별 파티션 목록을 함께 확인합니다.

## 2. 커밋과 장애 (2쪽)

커밋된 오프셋은 소비자가 재시작할 때 이어 읽을 위치입니다. Kafka 소비 커밋은 SQLite 업무 저장 트랜잭션과 다른 개념입니다. 처리 전에 위치부터 커밋하면, 장애로 처리하지 못한 이벤트를 재시작 시 건너뛸 수 있습니다. 이것이 B의 유실입니다. 반대로 처리 후 커밋 전 장애가 나면, 이미 처리한 이벤트를 다시 읽습니다. 이것이 C의 재수신 중복입니다.

여기서 유실은 브로커 원본 메시지 자체가 즉시 삭제되었다는 뜻이 아니라 해당 소비자 그룹의 처리 결과에서 누락되었다는 뜻입니다. 생산 수와 고유 처리 수의 차이를 대사해야 확인할 수 있습니다. 실습의 강제 종료 코드 42는 의도한 장애를 나타냅니다. 자동 커밋을 끄고 코드에서 시점을 결정합니다.

## 3. 중복 판정과 저장 방식 (3쪽)

이벤트 생성 시 만든 event_id를 재시도에도 유지해야 같은 이벤트의 반복 전달임을 알 수 있습니다. 다시 전송할 때마다 ID를 바꾸면 저장소가 다른 이벤트로 받아들입니다. 시민의 새로운 별도 민원을 단순히 내용이 비슷하다는 이유로 기술적 중복과 합치면 안 됩니다.

애플리케이션에서 먼저 조회하고 나중에 삽입하는 것만으로는 동시 처리 경쟁을 막기 어렵습니다. 저장소의 PRIMARY KEY/유니크 제약으로 같은 ID의 중복 삽입을 원자적으로 막습니다. 제약 없는 INSERT는 모든 수신을 새 행으로 남깁니다. INSERT OR IGNORE는 중복 행을 무시합니다. UPSERT는 한 행을 유지하면서 재관찰 횟수와 시각을 갱신합니다.

## 4. 멱등성과 지문 (3쪽)

같은 입력을 반복 적용해도 업무 상태가 한 번 적용한 결과와 같으면 멱등합니다. 이 실습의 지문은 `event_id, partition, offset, first_seen_at`을 정렬해 SHA-256을 계산한 앞 16자리입니다. `seen_count, last_seen_at`은 지문에서 제외합니다. 지문이 같다는 것은 코드가 정한 업무 필드가 같다는 증거이며, SQLite 전체 파일이나 모든 메타데이터가 똑같다는 뜻은 아닙니다.

전체 스트림을 다시 재생하는 D에서도 행 수와 업무 상태는 유지되어야 합니다. 총 관찰 수는 추가 재생 건수만큼 늘어나는 것이 정상입니다. 원래 한 번만 들어온 이벤트도 전체 리플레이 뒤에는 두 번 관찰되므로, D의 재관찰 이벤트 수는 C보다 늘 수 있습니다. 전달 보장과 업무 반영 보장을 구분해야 하며, 이번 실습을 Kafka 트랜잭션의 exactly-once 기능을 검증한 것으로 주장하지 않습니다.

## 5. 실습과 제출 (4~5쪽)

실제 저장소의 `run_chapter4.py`는 Kafka 실험과 중복 제거 실험을 함께 실행합니다. 중복 제거 코드는 제공된 스냅샷 입력을 읽으며 이번 Kafka 실험 결과로 자동 교체하지 않습니다. PDF에 있는 `cd ../chapter5`는 현재 파일 배치와 맞지 않습니다.

LMS에는 `ch4_delivery_report.json`과 `ch4_dedup_report.json`을 한 번의 제출에 함께 첨부하고 세 질문에 답합니다. 1번의 B·C는 전달 실험의 시나리오이고, 2~3번의 A·C·D는 저장 전략의 단계이므로 같은 문자를 혼동하지 않아야 합니다. 마감은 수업일 포함 7일 이내이며 LMS의 실제 마감도 확인해야 합니다.

추가 이론의 위치는 교수자 저장소 `lecture/docs/chapter4.md`(토픽·커밋·재시도)와 `lecture/docs/chapter5.md`(중복 제거 키·유니크 제약·지연 이벤트)입니다.
