# 실제 실행과 검증

교수자 chapter9 실행기·코드·requirements·피처 parquet 4개를 그대로 복사했다. `원본대조.json`의 SHA-256으로 원본 불변을 확인했다. 실제 MLflow SQLite 추적·레지스트리, scikit-learn 후보 훈련 2회와 선형회귀 재훈련 1회를 수행했으며 네트워크 모델 서버를 흉내 낸 결과가 아니다.

`실행로그.txt`에는 CH9_RUN_PASS, `실행상태.json`에는 종료 코드 0이 기록되어 있다. 설치 도중 먼저 실행한 시도의 ModuleNotFoundError는 별도 `의존성설치중_초기오류.txt`에 보관했고, 정상 실행 로그와 구분했다. `환경.json` 및 `requirements-lock.txt`는 실제 설치 버전이다. 강의의 scikit-learn 1.9.0과 달리 requirements가 버전을 고정하지 않아 1.9.1이 설치되었고, MAE·계수·승격·예측 결과는 강의와 같았다.

## 데이터 지문 차이의 검증

본인 데이터 지문은 `5ff6781dc27fbf737cb2df092a152eca85662f797546aeb6a42f82f04758d4d9`이다. Windows에서 원본 pandas CSV 직렬화가 CRLF 줄바꿈을 사용하기 때문이다. 같은 CSV의 줄바꿈만 LF로 바꾸어 해시를 계산하면 `96f6b6b3ce9dcdd1da62e0284e0ceea1ec2afec24c522f6df3221ad0ab31f49e`로 강의 지문과 일치한다. 제출 JSON이나 CSV를 강의 값에 맞춰 수정하지 않았다.

`검증.py`는 표준 라이브러리의 유리수로 baseline MAE=1, linear MAE=23/22, slope=9/22, intercept=81/22를 독립 계산하고, CSV 바이트 해시·승격 판정·별칭 예측·재현성을 대조한다. 개인 설계의 1.00/0.10도 별도로 적용해 v1 유지와 v2 반려를 확인했다.

## 보관과 재실행

원본 추적 DB와 모델·훈련 아티팩트는 `MLflow_실행원본.zip`에 보관했다. 실행 당시 절대 경로가 DB에 들어 있으므로 다른 PC에서 그대로 로드된다고 보장하지 않으며, 이동 환경에서는 원본 코드로 재생성한다. 압축 파일은 LMS 필수 제출물이 아니다.

가상환경에 `requirements-lock.txt`를 설치하고 **별도 작업 복사본**에서 `python practice/chapter9/run_chapter9.py`로 실행한다. 원본 실행기는 자기 data/output을 초기화하므로 보관된 제출 폴더에서 재실행해 결과를 덮어쓰지 않는다. Windows에서는 `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`을 설정한다.

보관 산출물의 독립 대조만 다시 하려면 저장소 루트에서 아래 명령을 실행한다.

```powershell
python "9주차 과제물/실행증빙/검증.py"
```

표 9.2의 업무 허용량·최소 개선 폭은 제공되지 않은 운영 수치를 꾸민 것이 아니라 명시적인 설계 가정이다. 실제 업무 도입 전 검증 필요성과 학생 사전 예측 미제공 상태를 설계표에 밝힌다. LMS 제출 완료는 확인하지 않았다.

폴더 분리 전 실행 로그·DB의 옛 절대 경로는 당시 실행증빙이므로 그대로 보존했다. 현재 경로는 `9주차 과제물`이며, 다른 위치에서 MLflow를 사용할 때에는 별도 복사본에서 재생성한다.
