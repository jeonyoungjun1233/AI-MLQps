# 실행 및 검증 기록

GitHub Actions Ubuntu에서 제공 실행기 `run_chapter6.py`를 실제 실행했다. Airflow DAG.test()를 이용하는 강의 방식으로 메타데이터 DB 마이그레이션, DAG 직렬화 및 태스크 실행을 수행했으며, 상시 스케줄러 서비스를 운영한 것은 아니다.

실행: https://github.com/jeonyoungjun1233/AI-MLQps/actions/runs/38114810747

Airflow 3.3.0, Python 3.13.16. 정확한 태스크 시작 시각은 제출 JSON에 UTC로 기록되어 있다. 설치 환경은 `pip-freeze.txt`, 설치 제약은 `constraints-3.13.txt`, 운영체제·커밋은 `environment.txt`에서 확인한다.

## 결과

- A: 7월 1~3일 모든 일별 태스크 success, gate=PASS, preservation_ok=true.
- B: 7월 1일 재실행 success. daily_summary.json 및 report.md의 전후 SHA-256 일치.
- C: 7월 4일 입력 없음. validate_input=failed, 나머지 4개 태스크=upstream_failed. 의도한 실패 실험이므로 run.log의 해당 FileNotFoundError는 전체 과제 실패가 아니다.
- D: 주간 롤업 success. 실제 산출물 있는 사흘만 합산. physical_total=60, mapped_total=54, missing_total=2, unmapped_total=3, dup_removed_total=1로 60=54+2+3+1.
- 실행기 종료 코드 0, CH6_RUN_PASS. `검증.py`에서 원본 입력을 별도로 세어 제출 JSON과 대조하고 PASS 확인.

## 재현 방법

GitHub 저장소 Actions → Week 6 Airflow exercise → Run workflow로 실행한다. 완료 후 week6-execution artifact에서 해당 실행의 원본 결과와 로그를 받을 수 있다. 새 실행은 시작 시각 등이 달라지므로 제출 JSON 전체 해시가 기존과 같을 필요는 없다.

Linux/macOS의 별도 체크아웃에서는 Python 3.13 가상환경을 만든 뒤 다음 명령을 실행할 수 있다. 제공 실행기는 자신의 data/output 전체를 초기화하므로 기존 제출물 보존이 필요하면 **별도 체크아웃/복사본에서** 실행한다.

```sh
python3.13 -m venv .venv
source .venv/bin/activate
pip install 'apache-airflow==3.3.0' --constraint '6주차 과제 완성본/실행증빙/constraints-3.13.txt'
python '6주차 과제 완성본/practice/chapter6/run_chapter6.py'
```

보관한 결과의 입력 대조만 다시 수행하려면 저장소 루트에서 다음 명령을 실행한다. Python 표준 라이브러리만 필요하며 Windows에서도 가능하다.

```sh
python '6주차 과제 완성본/실행증빙/검증.py'
```

Airflow 메타데이터 DB·런타임 설정은 제출·Git 보관 대상에서 제외했다. 강의의 실행 전 예측 활동은 사용자가 작성한 예측이 제공되지 않아 수행했다고 기록하지 않았다. 위 상태는 실제 실행 후 관찰이다.
