표 3.4 로컬 구성 설계표 - 실행 결과 및 원본 대조를 반영한 최종본
사전 설계·예측 기록은 제공되지 않아 재구성하지 않았으며, 아래 표는 실행 후 원본과 대조한 최종 구성이다.

계층: 수집
포함 여부
(예/미룸): 예
최종 선택 서비스: kafka; zookeeper
열 호스트 포트: kafka: 9092, 29092; zookeeper: 2181
무엇에 의존하는가: kafka → zookeeper; (service_healthy); ※ JSON에서 누락
근거 및 추가 시점: 실시간 민원 유입의 생산·소비 속도 차이를 완충하고 원천 로그를 되감기 위해 Kafka를 둔다; 이 구성의 Kafka는 ZooKeeper에 의존하며 로그 보존 설정은 168시간(7일)이다.

계층: 저장
포함 여부
(예/미룸): 예
최종 선택 서비스: postgres
열 호스트 포트: 5432
무엇에 의존하는가: 명시적 depends_on 없음
근거 및 추가 시점: 원천·가공 데이터를 보존하여 재처리와 감사에 대비한다; postgres_data 볼륨을 사용하는 저장 기반을 두되 실제 이벤트 적재 동작은 이번 정적 분석에서 검증하지 않았다.

계층: 처리
포함 여부
(예/미룸): 미룸
최종 선택 서비스: 현재 없음; 추후 Spark·Airflow
열 호스트 포트: 현재 없음
무엇에 의존하는가: 현재 없음
근거 및 추가 시점: 발주 조건에서 스트리밍 집계·배치 정제를 제외했다; 현재 계층 구분 관찰과 3~5장 진행에 불필요하고 설정 부담이 커서 스트리밍 처리는 6장, 배치·오케스트레이션은 7장에 추가한다.

계층: 서빙
포함 여부
(예/미룸): 미룸
최종 선택 서비스: 현재 없음; 추후 FastAPI
열 호스트 포트: 현재 없음
무엇에 의존하는가: 현재 없음
근거 및 추가 시점: 현재 요구는 유입 현황 대시보드이므로 별도 조회·예측 API 없이 진행 가능하다; 서비스 제공 실습이 필요한 10장에 추가하며, 미리 구축하는 학습 부담을 줄인다.

계층: 모니터링
포함 여부
(예/미룸): 예
최종 선택 서비스: prometheus; grafana; kafka-ui
열 호스트 포트: prometheus: 9090; grafana: 3000; kafka-ui: 8080
무엇에 의존하는가: grafana → prometheus; kafka-ui → kafka; prometheus: 명시 없음
근거 및 추가 시점: 유입 현황을 대시보드로 확인하고 침묵 실패를 감지할 관찰 기반이다; Prometheus는 메트릭 수집, Grafana는 시각화, Kafka UI는 개발용 Kafka 관찰을 담당한다.

3단계 대조 기록
서비스 수 | 기록 없음 | 6개 | 6개 | 수집 2 + 저장 1 + 모니터링 3; 계층과 서비스는 1:1이 아님
호스트 포트 수 | 기록 없음 | 7개 | 7개 | Kafka가 9092와 29092 두 포트를 호스트에 매핑함
의존성 수 | 기록 없음 | 2건 | 3건 | 맵 형태의 kafka → zookeeper를 교수자 파서가 누락함

의존성의 방향은 “서비스 → 선행 서비스”이며 depends_on 선언을 센다; 환경변수에 있는 연결 주소는 별도 의존성 건수로 합산하지 않는다.
교수자 코드는 리스트 형태의 depends_on만 읽어 맵 형태인 kafka → zookeeper(service_healthy)를 누락한다; 설계표에는 3건을 반영하고 제출 JSON의 2건은 수정하지 않았다.
Kafka의 9092는 호스트 클라이언트용, 29092는 컨테이너 통신용 리스너이며 이 Compose는 둘 다 호스트에 매핑한다.
본 실습은 구성 정적 분석에 성공했으며 실제 서비스 구동·포트 수신·데이터 적재·보안 개선 적용을 검증한 것은 아니다.

1. compose_path는 C:\Users\junyj\Desktop\AI데이터개발MLQps\3주차 과제 완성본\practice\chapter3\docker-compose.yml 이고 generated_at은 2026-09-20T02:27:06+00:00 이다. compose_path는 실행 시 읽은 Compose 파일의 절대 경로이므로 사용자 계정명과 저장소를 저장한 폴더 위치에 따라 학생마다 다르다.

2. 산출물에 기록된 서비스와 호스트 포트는 zookeeper(2181), kafka(9092, 29092), postgres(5432), prometheus(9090), grafana(3000), kafka-ui(8080)로 총 6개 서비스와 7개 포트이다. 실행 전 서비스 수 예측 기록이 없어 예측과의 불일치 여부는 판정할 수 없다. 수집 계층에 2개, 저장 계층에 1개, 모니터링 계층에 3개의 서비스가 배치되므로 계층 수와 서비스 수는 같지 않다.

3. 보안 경고 두 건은 “postgres: weak/default password in POSTGRES_PASSWORD”와 “grafana: weak/default password in GF_SECURITY_ADMIN_PASSWORD”이다. 검수 요구사항: PostgreSQL과 Grafana의 비밀번호는 기본값을 사용하지 않고 외부 환경변수 또는 시크릿 저장소에서 주입하며, 검수 시 Compose 및 저장소에 비밀번호 평문이 없음을 확인하고 기본 비밀번호 인증 실패와 주입한 비밀번호 인증 성공을 비밀값을 제외한 시험 기록으로 제출해야 한다.
