# 실행 범위와 재현 방법

## 실제 실행과 가정의 구분

교수자 chapter7 실행기·실습 코드·입력 스냅샷을 수정 없이 개인 폴더에 복사했다. 입력은 제공된 6주차 일별 집계 스냅샷이며 실시간 민원 API를 호출한 것이 아니다. Feast 0.64.0의 실제 엔진으로 parquet 생성, 정의 등록, 시점 조인, materialize, SQLite 온라인 조회, 일관성 대조를 실행한다.

Windows 시도에서는 UTF-8 설정 전 인코딩 오류가 발생했고, 설정 후에도 원본 코드의 Windows 절대경로를 registry가 URL scheme `c`로 해석해 실패했다. 두 오류 로그를 보관하며 성공 실행과 구분한다. 원본 코드를 수정하지 않고 GitHub Actions Ubuntu/Python 3.13에서 실행했다.

추가 `TTL검증.py`는 실제 배치를 나흘 기다리거나 강제로 실패시킨 실험이 아니다. 7월 4~7일 집계 공급이 없다는 조건을 고정 입력으로 표현하고, 네 번째 미갱신일에 해당하는 7월 8일 09:00 UTC를 오프라인 샘플 기준 시점으로 지정한 조회 실험이다. 마지막 피처 시각은 7월 4일 00:00 UTC이며 간격은 105시간으로 TTL 72시간을 넘는다. 온라인 조회는 실행 당시 실제 시각에 했으며 시계를 변경하지 않았다. 원본 제출 JSON에는 추가 실험 값을 삽입하지 않는다.

## TTL 해석의 근거

- 강의 PDF 4~6쪽: 최신값 대조와 시점 조인, TTL 밖 샘플 탈락.
- [Feast 공식 SQLite 문서](https://docs.feast.dev/reference/online-stores/sqlite): 최신값을 보존하며 조회 시 TTL 적용과 만료 데이터 삭제를 지원하지 않는다고 명시한다.
- [Feast 공식 시점 조인 문서](https://docs.feast.dev/getting-started/concepts/point-in-time-joins): TTL은 조회 실행 시각이 아니라 각 훈련 샘플 기준 시각에서 거슬러 올라가는 범위다.
- 실제 설치된 Feast 0.64.0의 `feast/infra/online_stores/sqlite.py` 온라인 읽기와 추가 조회 실험을 함께 대조했다.

따라서 이 실습의 온라인 값을 TTL 3일이 지났다는 이유만으로 자동 None 또는 0이라고 답하면 부정확하다. 또한 `online` 요약에는 건수와 비율만 있어 값 일치만으로 신선도를 알 수 없으므로, 원천 event_timestamp 및 마지막 갱신 시각을 별도로 감시해야 한다. 오래된 시점의 샘플까지 모두 사라진다는 뜻도 아니며, 각 샘플의 기준 시점에 TTL을 적용한다.

## 재현

GitHub Actions → **Week 7 Feast exercise** → **Run workflow**로 실행하면 `week7-execution` artifact에 실습 원본 결과와 추가 TTL 조회 결과가 저장된다. 환경은 `requirements-lock.txt`, `environment.txt`, 실행은 `run.log`, 추가 조회는 `ttl.log`에서 확인한다.

Linux에서 별도 복사본을 만들고 다음과 같이 실행할 수도 있다. 원본 실행기는 자기 `data/output`을 초기화하므로 보관용 완성본에서 덮어쓰기 재실행하지 않는다.

```sh
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r '7주차 과제 완성본/실행증빙/requirements-lock.txt'
export FEAST_USAGE=False
python '7주차 과제 완성본/practice/chapter7/run_chapter7.py'
python '7주차 과제 완성본/실행증빙/TTL검증.py'
```

보관된 JSON을 원천과 대조하는 검증은 Windows에서도 표준 Python만으로 실행할 수 있다.

```sh
python '7주차 과제 완성본/실행증빙/검증.py'
```

PDF 9쪽의 `CH8_RUN_PASS`는 실제 제공 코드의 `CH7_RUN_PASS`와 다르므로 실제 출력으로 판정한다. PDF 8쪽의 학생 실행 전 예측은 제공되지 않았으므로 작성했다고 기록하지 않는다. 이번 최종 제출 4문항 답안과 실행 후 관찰은 별도로 작성한다.
