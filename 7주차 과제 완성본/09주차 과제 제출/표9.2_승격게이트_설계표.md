# 표 9.2 승격 게이트 설계표 최종본

AI 데이터개발과 MLOps | 전영준 | 202373020

## 설계 전제

요구사항에는 상담원의 처리 용량, 현행 수작업 배치 오차, 교체 비용의 수치가 없다. 따라서 아래 **평균 절대 오차 1건 허용 및 최소 개선 0.10건은 교육용 설계 가정**이며 실제 기관에서 측정된 기준이 아니다. 예측 오차로 대기 시간과 유휴 인력이 발생한다는 요구와 월 1회 계획 변경 비용을 수치화한 제안이며, 운영 도입 전에 처리 용량·현행 오차·변경 비용으로 검증해야 한다.

| 항목 | 내가 정한 값(설계안) | 근거(요구사항과 연결) |
|---|---|---|
| 승격 판정 지표 | 교육용 대조는 `train_mae`(건, 낮을수록 좋음); 운영 승인은 별도 시간 분리 holdout MAE와 지역별 과소·과대 예측 검수를 요구 | 지역구별 익일 민원 예측은 과소 예측 시 대기, 과대 예측 시 유휴 인력을 만든다; 건수 단위 오차로 해석하되 6쌍의 훈련 오차를 일반화 성능으로 주장하지 않는다 |
| 절대 게이트 임계값 | 교육용 `train_mae <= 1.00`; 하루·지역구당 평균 1건의 오차를 대응 가능한 범위로 가정; 운영에서는 검증된 용량 기준으로 holdout MAE 한도를 확정 | 오차가 인력 계획에 미치는 영향을 기준으로 정한다; 인력 1명이나 최대 오차 1건을 뜻하지 않으며 실제 허용량 자료가 없는 가정이다 |
| 상대 조건(champion 대비 개선 폭) | 동일 데이터·평가법에서 `champion_mae - candidate_mae >= 0.10`; 최초 등록은 비교 대상이 없어 상대 조건 제외, 절대 게이트와 별도 검수는 적용 | 월 1회 재훈련과 모델 교체 때 운영 계획도 바뀌므로 미미한 개선으로 교체하지 않는다; MAE 0.10은 예측 10회당 절대오차 합 1건 감소를 최소 이득으로 가정한 값이다 |
| 재현성·데이터 지문 요건 | 정규화 훈련 CSV의 전체 SHA-256과 사본, 코드 커밋, 파라미터·환경을 보관; 동일 입력 재훈련의 MAE·계수 일치 확인; 데이터 정정 시 후보와 champion을 같은 평가 데이터로 다시 비교 | 확정 집계도 정정 재실행으로 바뀌므로 파일 경로만으로 동일성을 보장하지 못한다; 감사와 담당자 교체 후에도 같은 모델을 재현해야 한다 |
| 운영 태그 최소 집합 | owner, purpose, data_source, data_period 및 코드 버전·전체 데이터 지문·평가 분할/지표 버전·gate_version·승인자/시각·판정 이유를 연결 기록 | 모델 교체마다 ‘왜 바꿨는가’에 답해야 하고 담당자가 2년마다 바뀐다; 원본 코드의 태그는 앞의 4개이며 나머지는 본 설계에서 제안한 운영 보완 항목이다 |
| 승인 주체와 예외 승인 경로 | 훈련 담당자는 등록만, 독립 검수자는 재현성·업무 영향 확인, 운영 책임자는 승인 후 champion 별칭 이동; 예외는 사유·위험·유효기간·복귀 버전이 있는 서면 승인 후 별도 권한자가 수행 | 인력 계획 변경과 감사 요구 때문에 자동 수치 판정과 사람의 승인을 분리한다; 역할 설계이며 실제 승인자나 승인 사실을 만들어 적은 것이 아니다 |
| 이 게이트가 깨지는 조건(3단계 대조 반영) | 느슨한 쪽: 훈련 MAE만 낮고 미래 오차·특정 지역 과소 예측이 크면 부적합 모델을 통과시킨다; 엄격한 쪽: 1.00/0.10이 실제 업무보다 엄격하면 후보가 계속 반려되어 낡은 champion이 남는다; 데이터 정정 후 서로 다른 지문·평가집합의 점수를 비교하거나 필수 holdout 지표가 기록되지 않아도 게이트가 무효다; 이번 원본 실습은 train_mae만 기록하므로 운영 승인은 검증되지 않는다 | 결과를 보고 임계값을 유리하게 바꾸지 않고 실패 조건을 보완했다; 임계값은 업무 자료로 재검증하고 기준 변경은 버전·승인 기록을 남기며, 장기 반려 시 현행 모델의 품질·신선도를 별도로 감시한다 |

## 실행 전 기록의 범위

`실행증빙/실행전_설계가정.json`에 실제 훈련 실행 전에 지원 도구의 설계안을 저장했다. 다만 강의 예시 결과는 이미 읽었고 학생 본인의 독립적인 실행 전 예상은 제공되지 않았으므로, 예측 활동을 학생이 수행했다고 주장하지 않는다. 아래는 실행 후의 실측 대조이다.

## 3단계: 실측에 내 게이트 적용

원본 스크립트는 수정하지 않아 `train_mae <= 1.05` 및 기존 champion보다 엄격히 작은 MAE로 판정한다. 개인 설계표의 1.00/0.10은 **별도 대조 규칙**이며 제출 JSON의 metric_gate 값을 바꾼 것이 아니다.

| 후보 | 실제 train_mae | 스크립트 판정 | 내 절대 기준 <=1.00 | 내 상대 기준 >=0.10 개선 | 내 최종 교육용 대조 |
|---|---:|---|---|---|---|
| v1 baseline_mean | 1.0000 | 절대 통과, 최초 champion 승격 | 통과 | 최초 등록으로 적용 제외 | 재현성 검수 확인 후 최초 후보 v1 지정 |
| v2 linear | 1.0455 | 절대 통과, 상대 개선 없어 반려 | 실패 | 1.0000 - 1.0455 = -0.0455로 실패 | v2 반려, v1 유지 |

최종 champion을 v1로 유지하는 결과는 같지만, 스크립트의 v2는 상대 조건만 실패하고 내 설계에서는 절대·상대 조건 모두 실패한다. 경계 예시로 후보 MAE가 0.9990이면 스크립트는 개선으로 승격하지만, 내 설계는 개선 폭 0.0010 < 0.10으로 반려하므로 무의미한 월별 교체를 줄이는 대신 유용한 작은 개선까지 막을 위험이 있다. 실제 재현성 검사와 별칭 로드 결과는 제출 JSON과 실행증빙에서 확인하며, 위 표는 운영 승인 사실을 뜻하지 않는다.
